- `www.exhilaration.uk` — verified=false

Live DNS check (`check_domain_status`) for BOTH domains:

This is the cause. Cloudflare custom-hostname verification and SSL certificate issuance **cannot begin until the domain's DNS actually points at our edge**. Right now the registrar's A records for both the apex and the www subdomain do not resolve to the expected IPs, so verification is blocked on the user side — it is not stuck on our end, and it is not an error in the pipeline.

## What is needed to fix
This is a **user DNS action**, not a code/manifest/platform issue.
1. In Deployment Panel → Domains, copy the exact DNS records shown for `exhilaration.uk` and `www.exhilaration.uk`.
2. At the domain registrar / DNS provider, set those records verbatim (A record for the apex, and the record shown for `www`). Current records do not match the expected IPs.
3. Wait for DNS propagation, then verification + SSL issuance proceed automatically.

## Typical timing (once DNS is correct)
- DNS propagation: usually minutes, but can take up to 24–48h depending on the registrar and the previous record's TTL.
- Domain verification + Cloudflare SSL certificate issuance: typically a few minutes to ~1 hour after DNS resolves correctly.
- Meanwhile the default URL `https://event-artist-hub-4.emergent.host` works and is unaffected — the app is fully usable there now.
